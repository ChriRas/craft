# Stack-Pack — Python (no web framework)

The code-near personality layer for a Python 3.11 to 3.15 project without a web framework — a library, a command-line
tool, a script collection or a service wired by hand — managed with uv, kept clean with Ruff and mypy, and tested with
pytest. It is loaded on top of the Senior-Developer baseline by `/craft:build`, `/craft:test`, `/craft:refactor` and
`/craft:review` when `rules.md` declares it in its `## Personality` block. A project on Django, FastAPI or another web
framework wants a pack of its own; this one covers the language and the tooling only. Project-specific conventions —
domain rules, exact tool commands, the supported Python range — live in the project's own `rules.md`, not here. Versions
and tool behaviour below were verified on 2026-11-11 (see `## Sources`); a newer release may have moved since.

## Stack

- **Language** — Python 3.14 (3.15 is out too): full type hints, `dataclass(frozen=True, slots=True)`, `pathlib`, f-strings,
  `match`, context managers, `enum.StrEnum`. Annotations are evaluated lazily from 3.14 on, so a forward reference needs
  no quotes. Support on 2026-11-11: 3.15 and 3.14 get bugfix releases, 3.13, 3.12 and 3.11 security fixes only (3.11 ends
  in October 2027); 3.10 ended on 2026-10-01. The floor a project may use is its `requires-python`.
- **Environment and dependencies** — uv 0.13: `pyproject.toml` as the one configuration, `uv.lock` committed, the
  environment in `.venv`, the interpreter pinned in `.python-version`, development tools in `[dependency-groups]`
  (PEP 735), run through `uv run` (see `references/project-patterns.md`).
- **Quality** — Ruff 0.17 for lint and format (`ruff check`, `ruff format`); since 0.16 its default rule set is broad and
  already sorts imports. mypy 2.4 with `strict = true` for types. A faster or alternative checker is a project's choice
  (see `## Existing Projects`).
- **Tests** — pytest 9 configured in `[tool.pytest]` with `strict = true`; pytest-cov for coverage, pytest-asyncio for
  `async def` tests (see `references/test-patterns.md`).

## Existing Projects

The Senior-Developer baseline's existing-toolchain rule applies. Read `pyproject.toml` and the files at the project root
first and follow what they declare:

- **pip + venv with `requirements*.txt`** — a `requirements.txt` (often `requirements-dev.txt`), no lock file, a `.venv`
  or `venv/`. Create the environment with `python -m venv .venv`, install with `python -m pip install -r requirements.txt`,
  add a dependency by adding its line and installing again (regenerate with `python -m pip freeze > requirements.txt` only if
  the file already is a full freeze), run tests with `python -m pytest`. Do not introduce uv or a lock file unasked.
- **pip-tools** — a `requirements.in` next to a compiled `requirements.txt` ("autogenerated by pip-compile" in its header).
  Add the dependency to the `.in` file, run `pip-compile -o requirements.txt requirements.in` (or `pip-compile
  --upgrade-package <name>` for one), then `pip-sync` in a venv (`python -m venv .venv`); tests: `python -m pytest`.
- **Poetry** — `poetry.lock` and a `[tool.poetry]` table (or `[project]` plus `[build-system]` with `poetry-core`). Add with
  `poetry add <name>` (`--group dev` for tools), lock with `poetry lock` (it keeps locked versions; `--regenerate`
  re-resolves), create the environment with `poetry install` (or `poetry sync`), run tests with `poetry run pytest`.
- **Pipenv** — a `Pipfile` and `Pipfile.lock`. Add with `pipenv install <name>` (`--dev` for tools), lock with
  `pipenv lock`, install exactly the lock with `pipenv sync`, run tests with `pipenv run pytest`.
- **`setup.py` / `setup.cfg`** — metadata and `install_requires` in those files, often no `pyproject.toml`. Keep the format;
  install in editable mode with `python -m pip install -e .` (calling `python setup.py install` or `develop` is
  deprecated), add a dependency under `install_requires`, run the tests as the project does. Moving to `pyproject.toml`
  is a slice of its own.
- **Black, Flake8 and isort instead of Ruff** — `[tool.black]`, a `.flake8` / `tox.ini` / `setup.cfg` Flake8 section (Flake8
  does not read `pyproject.toml`), `[tool.isort]` or `.isort.cfg`, often in `.pre-commit-config.yaml`. Run `black --check .`,
  `flake8` and `isort --check .`; format new code to match, and never reformat files the slice does not touch. Ruff's
  formatter is close to Black but not identical, so do not mix the two on one tree.
- **A different type checker** — Pyright (`pyrightconfig.json` or `[tool.pyright]`), ty (`[tool.ty]`, beta, 0.0.x
  versions without a stable API) or Pyrefly (`[tool.pyrefly]` / `pyrefly.toml`): run the one the project declares and
  write annotations all four accept; do not add mypy next to it. **No checker at all** — write typed code anyway, name a
  checker as a follow-up, do not add one to the slice.
- **`unittest` instead of pytest** — `unittest.TestCase` classes, no pytest in the dependencies; run
  `python -m unittest` (it discovers `test*.py` from the top-level directory). pytest also runs `TestCase` classes, but a
  new test follows the style of its neighbours and the slice adds no second runner.
- **An older Python** — `requires-python` (or `python_requires`, `.python-version`, a `tox` / CI matrix) sets the floor; use
  no feature above it (`match` 3.10, `tomllib` and `except*` 3.11, `type` statement and generic syntax 3.12, `TypeIs` and
  `warnings.deprecated` 3.13, t-strings and lazy annotations 3.14). 3.10 is end-of-life: say so, do not upgrade it silently.

## Build Order

When a slice spans several layers, implement in dependency order:

1. Project and tooling — `pyproject.toml`, the src layout, `uv.lock`, Ruff, mypy and pytest configuration.
2. Domain types — frozen dataclasses, enums, exception classes, type aliases.
3. Pure logic — functions and classes that take their dependencies as arguments.
4. Adapters — filesystem, network, database, clock and subprocess behind small interfaces.
5. Entry points — the CLI or service `main()` that parses input, wires everything and maps errors to exit codes.
6. Tests — alongside each layer or right after; `ruff check`, `ruff format --check`, mypy and pytest pass before a layer counts as done.

## Anti-Patterns

- Untyped public functions, `Any` where a dataclass, `TypedDict` or `Protocol` fits, and `# type: ignore` without an error code.
- A mutable default argument, a module-level singleton that does work on import, or `global` state.
- A bare `except:` or `except Exception: pass`; a `raise` inside `except` without `from`; strings where an exception class belongs.
- `os.path` string juggling, `open()` without an explicit `encoding`, and `subprocess` with `shell=True` on input that is not constant.
- `pip install` into the system interpreter, an unpinned application dependency, or a committed `.venv`.
- A business rule in `if __name__ == "__main__":` or a `main()` that tests cannot call; `print` for diagnostics, or a configured logging root, in library code.
- An unreferenced `asyncio.create_task(...)` result, a blocking call inside `async def`, or `asyncio.run` nested in a running loop.
- `select = ["ALL"]` in Ruff (every release adds rules), a growing `ignore` list or `per-file-ignores` hiding new findings.
- Tests that sleep, hit the network or the wall clock, depend on order, or patch where an object is defined instead of where it is used.
